# Model Card

## Data

Training data is generated from simulated sensor and production-line data. It is not real Seagate data and not proprietary factory data.

## Models

### Failure classifier

Models:

- Logistic Regression baseline
- Random Forest
- GradientBoostingClassifier fallback
- optional XGBoost when explicitly enabled

Target:

```text
failure_label
```

Metrics:

```text
accuracy
precision
recall
f1
roc_auc
pr_auc
confusion_matrix
false_negative_count
```

Recall is important because false negatives can represent missed risk warnings.

### RUL regressor

Models:

- RandomForestRegressor
- GradientBoostingRegressor

Target:

```text
rul_estimate_hours
```

Metrics:

```text
MAE
RMSE
R2
```

RUL is simulated and should not be interpreted as real machine lifetime.

### Anomaly detector

Model:

```text
IsolationForest
```

Outputs:

```text
anomaly_score
anomaly_flag
```

## Feature columns

The model uses raw sensor/process fields plus engineered features such as:

- temperature_delta
- vibration_severity_index
- torque_per_speed
- motor_load_index
- tool_wear_rate
- rolling_vibration_mean
- cycle_time_drift
- defect_rate_rolling_mean
- equipment_process_risk_index

## Data leakage prevention

- Data is sorted by timestamp.
- Sensor-production join uses historical sensor data only.
- Rolling features use `shift(1)`.
- Train/test split is chronological.

## Intended use

Portfolio demonstration, interview discussion, and simulated workflow validation.

## Out-of-scope use

Real factory decision automation, warranty decisions, safety decisions, or closed-loop machine control.

## Synthetic label and leakage controls update

The current repository uses synthetic labels for portfolio demonstration. Metrics from these labels validate pipeline behavior, not real factory accuracy.

Leakage controls:

- `FEATURE_COLUMNS` are explicitly separated from target and synthetic label columns.
- `TARGET_COLUMNS`, `SYNTHETIC_LABEL_COLUMNS`, and `EXCLUDED_LEAKAGE_COLUMNS` are blocked from training features.
- `hidden_degradation_state` is generated by the synthetic simulator but is never used as a training feature.
- `equipment_process_risk_index` is retained only as an operational baseline score and is excluded from training.
- Model artifacts store the exact feature list used for training.
- Pytest includes leakage tests.

What metrics prove:

- the pipeline can train and evaluate models end-to-end;
- artifacts and metrics are created;
- the model registry records metadata;
- the inference API can load and use trained artifacts.

What metrics do not prove:

- real factory failure prediction accuracy;
- real RUL accuracy;
- real Seagate process behavior;
- validated production deployment performance.

Real validation would require real maintenance history, process labels, downtime logs, failure events, censored data handling, process owner review, and factory acceptance testing.
